# AI-Assisted Text Wireframes (ASCII Layout)

เอกสารรวบรวม Prompt และผลลัพธ์ Text Wireframe รูปแบบ ASCII Layout สำหรับระบบ **Inventory Management** จำนวน 3 หน้าจอหลัก ได้แก่:
1. **หน้าเข้าสู่ระบบ (Login Page)**
2. **หน้าแดชบอร์ดสรุปยอดและแจ้งเตือนสต็อกต่ำ (Dashboard Page)**
3. **หน้าเพิ่มสินค้าใหม่ (Add Product Page - รองรับสินค้าจับต้องได้และสินค้าดิจิทัล)**

---

## Screen 1: หน้าเข้าสู่ระบบ (Login Page)

### Prompt ที่ใช้สั่ง AI:
```text
ช่วยออกแบบ text wireframe (ASCII layout) สำหรับ "หน้า Login" ของระบบ Inventory Management
กลุ่มผู้ใช้: พนักงานคลังสินค้า ทักษะเทคโนโลยีระดับ 2/5 ใช้งานผ่าน PC เป็นหลัก
ข้อกำหนด Usability:
- กล่องเข้าสู่ระบบอยู่กึ่งกลางหน้าจอ สะอาดตา ชัดเจน
- ฟิลด์: ชื่อผู้ใช้ (Username)*, รหัสผ่าน (Password)*
- ตัวเลือกจำการเข้าสู่ระบบ (Remember Me) และลิงก์ลืมรหัสผ่าน
- ปุ่ม "เข้าสู่ระบบ" (Primary Button) เด่นชัด
- แสดงสถานะ Validation Error เมื่อกรอกข้อมูลไม่ถูกต้อง
ข้อกำหนด Accessibility:
- ทุกฟิลด์มี Visible Label ถาวรเหนือช่องกรอก (ไม่ใช่ Placeholder อย่างเดียว)
- Required field มีเครื่องหมาย * ชัดเจน
- Error message มีไอคอนและข้อความอธิบายวิธีแก้ชัดเจน
- เรียงลำดับ Tabindex จากบนลงล่างอย่างถูกต้อง
ขอผลเป็น ASCII layout พร้อมคำอธิบายว่าแต่ละองค์ประกอบช่วย usability อย่างไร
```

### คำอธิบาย Usability & Accessibility:
- **Card-based Center Layout:** จัดวางฟอร์มตรงกลาง ช่วยลดสิ่งรบกวนสายตา เหมาะกับผู้ใช้ระดับทักษะ 2/5
- **Visible Permanent Labels:** กำกับเหนือช่องกรอก ทำให้ผู้ใช้ไม่ลืมบริบทแม้เริ่มพิมพ์ข้อความ
- **Show Password Toggle:** เพิ่มตัวเลือกแสดงรหัสผ่าน ช่วยลดปัญหาพิมพ์ผิดสำหรับผู้ใช้สูงวัยหรือผู้ที่มีปัญหาการมองเห็น
- **Descriptive Error Box:** มีไอคอน `[!]` ควบคู่กับข้อความคำแนะนำ ไม่พึ่งพาการใช้สีแดงเพียงอย่างเดียว

## Screen 2: หน้าแดชบอร์ดสรุปยอดและแจ้งเตือนสต็อกต่ำ (Dashboard Page)

### Prompt ที่ใช้สั่ง AI:
```text
ช่วยออกแบบ text wireframe (ASCII layout) สำหรับ "หน้า Dashboard" ของระบบ Inventory Management
กลุ่มผู้ใช้: ผู้จัดการและพนักงานคลังสินค้า
ข้อกำหนด Usability:
- แถบนำทางด้านซ้าย (Sidebar) แสดงเมนูหลักชัดเจน ไฮไลต์หน้าปัจจุบัน
- สรุปตัวเลขสถิติสำคัญ (KPI Cards): มูลค่ารวม, จำนวนรายการสินค้าทั้งหมด, จำนวนสินค้าใกล้หมด (Low Stock)
- การ์ดแจ้งเตือนสต็อกต่ำ (Low Stock Alert Table) แสดงรายการสินค้าที่มี stock <= 5 ชิ้น พร้อมปุ่มลัดสำหรับเติมสต็อก
- ตารางแยกชนิดสินค้าระหว่างสินค้าจับต้องได้ (Physical) และสินค้าดิจิทัล (Digital Files) ชัดเจน
ข้อกำหนด Accessibility:
- ใช้ Contrast ตามเกณฑ์ WCAG AA (#111827 บนพื้นขาว, #1E40AF สำหรับ Active State, #B45309 สำหรับ Low Stock Warning)
- ข้อความแจ้งเตือนมีไอคอนกำกับ
ขอผลเป็น ASCII layout พร้อมคำอธิบาย
```

### คำอธิบาย Usability & Accessibility:
- **Clear Information Hierarchy:** ด้านบนแสดง KPI Cards สำหรับดูภาพรวมอย่างรวดเร็ว ถัดลงมาเป็นการแจ้งเตือนสต็อกต่ำที่ต้องจัดการด่วน
- **Explicit Product Type Badges:** มีป้ายกำกับชัดเจน `[จับต้องได้]` และ `[ดิจิทัล]` ป้องกันความสับสนของพนักงานโดยไม่ต้องเดาจากชื่อ
- **Direct Action Buttons:** ตารางสินค้าใกล้หมดมีปุ่ม `[+ เติมของ]` โดยตรง ช่วยลดคลิกในการทำงาน
- **Dual Indicators:** ใช้ทั้งไอคอน `[!]` และการเน้นข้อความสำหรับสินค้าสต็อกต่ำ เพื่อรองรับผู้ใช้ที่มีภาวะตาบอดสี

## Screen 3: หน้าเพิ่มสินค้าใหม่ (Add Product Page)

### Prompt ที่ใช้สั่ง AI:
```text
ช่วยออกแบบ text wireframe (ASCII layout) สำหรับ "หน้า Add Product" ของระบบ inventory
กลุ่มผู้ใช้: พนักงานคลังทักษะเทคโนโลยีระดับ 2/5 ใช้ PC เป็นหลัก
ข้อกำหนด usability
- ฟอร์มมีฟิลด์: ชื่อสินค้า*, รหัสสินค้า*, ชนิดสินค้า* (จับต้องได้ หรือไฟล์ดิจิทัล), หมวดหมู่ (dropdown), จำนวน*, ราคา*, รูป (optional)
- ปุ่ม "บันทึกสินค้า" (primary) และ "ยกเลิก" (secondary) วางขวาล่าง
- ต้องแสดง state: validation error ใต้ฟิลด์ และ success message หลังบันทึก
ข้อกำหนด accessibility
- ทุกฟิลด์มี label ที่มองเห็น (ไม่ใช่ placeholder อย่างเดียว)
- required field มีเครื่องหมาย *
- error message อธิบายวิธีแก้ ไม่ใช่แค่ "ผิดพลาด"
- รองรับการสลับระหว่างสินค้าจับต้องได้ (ต้องระบุจำนวนสต็อก) และสินค้าดิจิทัล (แสดงช่องไฟล์/URL และปิดช่องจำนวนสต็อก)
ขอผลเป็น ASCII layout พร้อมคำอธิบายว่าแต่ละองค์ประกอบช่วย usability อย่างไร
```

### คำอธิบาย Usability & Accessibility:
1. **Radio Group Type Selector:** ตัวเลือกชนิดสินค้าวางไว้ที่ข้อแรก เพื่อให้ระบบปรับสภาพแวดล้อมของฟอร์มอัตโนมัติ (Dynamic Form Fields): หากเลือกสินค้าดิจิทัล ฟิลด์ "จำนวนเริ่มต้น" จะถูก Disable และระบุข้อความ "ไม่จำกัดจำนวน (ดิจิทัล)" พร้อมเปิดช่อง "อัปโหลดไฟล์ดิจิทัล / ลิงก์ดาวน์โหลด" ขึ้นมาแทน
2. **Persistent Visible Labels:** ทุกช่องมี Label กำกับอยู่ข้างบนอย่างถาวร แม้ผู้ใช้จะพิมพ์ข้อมูลไปแล้วก็ยังตรวจสอบได้ตลอดเวลา
3. **Actionable Inline Validation:** ข้อความแจ้งเตือน Error แสดงอยู่ใต้ช่องทันที โดยระบุชัดเจนทั้งไอคอน `[!]` และคำแนะนำวิธีแก้ไข เช่น *"ราคาต้องมากกว่าศูนย์ (เช่น 99.00 หรือ 590.00)"* แทนการเขียนข้อความห้วน ๆ ว่า "ผิดพลาด"
4. **Primary/Secondary Button Distinction:** ปุ่ม "บันทึกสินค้า" (Primary: `#1E40AF`) และปุ่ม "ยกเลิก" (Secondary: เส้นขอบเทา `#4B5563`) วางชิดมุมขวาล่างตามหลัก Z-pattern / F-pattern เพื่อให้เป็นจุดสิ้นสุดสายตาของผู้ใช้หลังจากกรอกฟอร์มครบถ้วน
