# Accessibility & Usability Review

รายงานการตรวจสอบความสอดคล้องตามมาตรฐานการออกแบบส่วนต่อประสานกับผู้ใช้ (Usability) และการเข้าถึงข้อมูล (Web Content Accessibility Guidelines - WCAG 2.1 ระดับ AA) ของ Mockup ระบบ Inventory Management

---

## ตาราง Checklist ตรวจสอบ Accessibility & Usability

| รายการตรวจ | ผ่าน หรือ ไม่ผ่าน | สิ่งที่แก้ / ข้อสังเกตเพิ่มเติม |
| :--- | :---: | :--- |
| **1. ข้อความหลักสี #111827 บนพื้นขาว มี contrast อย่างน้อย 4.5 ต่อ 1** | **ผ่าน** | สี `#111827` บนพื้นหลัง `#FFFFFF` มี Contrast Ratio สูงถึง **16.1 : 1** (สูงกว่าเกณฑ์ขั้นต่ำ 4.5:1 ของ WCAG AA และผ่านเกณฑ์ 7.0:1 ของระดับ AAA) ตัวอักษรคมชัด อ่านง่าย ไม่ทำให้สายตาล้า |
| **2. ปุ่ม Primary มี contrast เพียงพอ** | **ผ่าน** | ตัวอักษรสีขาว `#FFFFFF` บนพื้นหลังปุ่มสี Primary `#1E40AF` มี Contrast Ratio **8.5 : 1** (ผ่านเกณฑ์ WCAG AAA สำหรับ Normal Text) มองเห็นเด่นชัดและแยกจากพื้นหลังได้ทันที |
| **3. ทุกช่องกรอกมี label ที่มองเห็น** | **ผ่าน** | ทุกช่องอินพุตในหน้า Login และ Add Product มี `<label>` แสดงอยู่เหนือช่องกรอกตลอดเวลา (Persistent Labels) แม้ผู้ใช้เริ่มพิมพ์ข้อความ ป้ายกำกับจะไม่หายไปเหมือนการใช้ Placeholder เพียงอย่างเดียว |
| **4. ช่องที่บังคับกรอกมีสัญลักษณ์ชัด** | **ผ่าน** | ทุกฟิลด์ที่เป็น Required fields มีเครื่องหมายดอกจันสีแดง `*` ชัดเจน และมีคำชี้แจงหัวฟอร์มกำกับว่า `* จำเป็นต้องกรอกฟิลด์นี้` พร้อมระบุ `aria-required="true"` สำหรับผู้ใช้ที่ใช้ Screen Reader |
| **5. error ไม่ได้ใช้สีอย่างเดียว มีไอคอนและข้อความด้วย** | **ผ่าน** | ช่องที่มีข้อผิดพลาดไม่ได้ใช้เพียงกรอบสีแดงหรือตัวหนังสือสีแดง แต่มีไอคอนเครื่องหมายเตือน `[!]` ควบคู่กับข้อความคำแนะนำที่อธิบายวิธีแก้ไขชัดเจน เช่น *"ราคาต้องมากกว่า 0 บาท เช่น 590.00"* ทำให้ผู้มีภาวะตาบอดสี (Color Blindness) เข้าใจได้ทันที |
| **6. ลำดับการกด Tab เรียงบนลงล่าง ซ้ายไปขวา** | **ผ่าน** | ลำดับการนำทางด้วยแป้นพิมพ์ (Keyboard Focus Navigation) สอดคล้องตามโครงสร้าง Logical DOM Order จากซ้ายไปขวาและบนลงล่าง (ช่องที่ 1 -> 2 -> 3 -> 4 -> 5 -> 6 -> 7 -> ปุ่มยกเลิก -> ปุ่มบันทึก) ไม่มีข้ามช่อง |
| **7. ปุ่มมีชื่อบอกหน้าที่ชัด ไม่ใช่ OK หรือกากบาท** | **ผ่าน** | หลีกเลี่ยงการใช้คำกำกวมอย่าง "OK", "ตกลง" หรือเครื่องหมาย "X" โดยตั้งชื่อปุ่มระบุ Action ชัดเจน ได้แก่ *"บันทึกสินค้า (Save Product)"*, *"เข้าสู่ระบบ (Sign In)"*, *"ยกเลิก (Cancel)"*, และ *"[+ เติมสินค้า]"* |

## จุดที่ AI มักพลาดในงาน UI และนักศึกษาแก้เอง (อย่างน้อย 2 จุด)

จากการสังเกตผลการ Generate ส่วนติดต่อผู้ใช้และ Wireframe ของ AI coding assistant พบจุดบกพร่องสำคัญด้าน Usability และ Accessibility ซึ่งได้รับการตรวจจับและแก้ไข ดังนี้:

### จุดที่ 1: AI ใช้ Placeholder แทน Label ถาวร (Floating/Missing Labels)
- **พฤติกรรมที่ AI พลาด:** AI มักสร้างแบบฟอร์มโดยใส่ข้อความอธิบายเฉพาะในแอตทริบิวต์ `placeholder="กรอกชื่อสินค้า..."` โดยไม่มีแท็ก `<label>` แยกต่างหาก ซึ่งเมื่อผู้ใช้พิมพ์ตัวอักษรตัวแรก ข้อความ placeholder จะหายไปทันที ทำให้ผู้ใช้ระดับทักษะต่ำ (เช่น พนักงานคลังที่ต้องกรอกหลายช่อง) ลืมว่าช่องนี้คือข้อมูลอะไร และโปรแกรมอ่านหน้าจอ (Screen Reader) จะอ่านออกเสียงไม่ถูกต้อง
- **สิ่งที่นักศึกษาแก้ไข:** นำ `<label>` แบบถาวรมาวางไว้เหนือช่อง Input ทุกช่อง พร้อมระบุ `for="..."` ให้ผูกกับ `id="..."` ของช่องกรอกอย่างถูกต้อง และใช้ placeholder แสดงเฉพาะตัวอย่างรูปแบบข้อมูล (Format Hint) เท่านั้น

### จุดที่ 2: AI ใช้สีเทาอ่อนในการแสดงข้อความและเส้นขอบที่ Contrast ไม่ผ่านเกณฑ์ WCAG AA
- **พฤติกรรมที่ AI พลาด:** AI มักใช้ชุดสีเทาโมเดิร์นตามค่านิยมของดีไซน์เนอร์ เช่น ข้อความสีเทาอ่อน `#9CA3AF` บนพื้นหลังสีขาว `#FFFFFF` ซึ่งมี Contrast Ratio เพียง **2.8 : 1** (ไม่ผ่านเกณฑ์ WCAG AA ที่กำหนดขั้นต่ำ 4.5:1) ทำให้พนักงานคลังที่ใช้จอภาพความสว่างน้อยหรืออยู่ในห้องเก็บของที่มีแสงรบกวนอ่านข้อความได้ยากมาก
- **สิ่งที่นักศึกษาแก้ไข:** ปรับสีข้อความหลักทั้งหมดให้เป็น `#111827` (Contrast 16.1:1) และข้อความรอง (Secondary/Helper Text) ใช้สี `#4B5563` (Contrast 7.5:1 ผ่านเกณฑ์ AAA) พร้อมใช้สีข้อความแจ้งเตือนสต็อกต่ำเป็น `#B45309` (Contrast 5.4:1 ผ่านเกณฑ์ AA)

### จุดที่ 3: ข้อความแสดงความผิดพลาด (Error State) คลุมเครือและพึ่งพาเพียงสีแดง
- **พฤติกรรมที่ AI พลาด:** เมื่อมี Input Validation ล้มเหลว AI มักเปลี่ยนแค่สีกรอบเป็นสีแดงและแสดงข้อความห้วน ๆ เช่น *"Invalid Input"* หรือ *"เกิดข้อผิดพลาด"* โดยไม่ได้บอกว่าค่าที่ผิดคืออะไร และผู้ใช้ต้องแก้ไขอย่างไร
- **สิ่งที่นักศึกษาแก้ไข:** เพิ่มไอคอนรูปสามเหลี่ยมแจ้งเตือน `[!]` คู่กับข้อความอธิบายแนวทางแก้ไขแบบสร้างสรรค์ (Actionable Error Message) เช่น *"กรุณากรอกราคาต่อหน่วยเป็นตัวเลขมากกว่าศูนย์ เช่น 99.00 หรือ 590.00"* ช่วยให้ผู้ใช้เข้าใจและแก้ไขได้ด้วยตนเองทันที
